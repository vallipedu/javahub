Polymorphism in Java — Compile-time & Runtime

1. What is Polymorphism?

Polymorphism means many forms. In Java it allows the same operation (method call) to behave differently depending on the object that performs it. Polymorphism is fundamental to designing systems that are extensible, maintainable and loosely-coupled.

Real-world analogy (Automobile): the action start() applies to every vehicle, but how a vehicle starts differs — electric cars start silently, diesel engines crank, sports cars rev aggressively. The interface (start) is the same; the implementation differs.

2. Compile-time Polymorphism (Static Polymorphism)

Compile-time polymorphism is resolved during compilation. Java implements it using method overloading (same method name, different parameter lists). The compiler decides which method variant to invoke based on the call-site signature.

class Calculator { int add(int a, int b) { return a + b; } int add(int a, int b, int c) { return a + b + c; } double add(double a, double b) { return a + b; } } public class Test { public static void main(String[] args) { Calculator c = new Calculator(); System.out.println(c.add(10, 20)); // -> 30 System.out.println(c.add(10, 20, 30)); // -> 60 System.out.println(c.add(2.5, 3.5)); // -> 6.0 } }
Output (conceptual): 30 60 6.0

Why compile-time polymorphism matters

  • Simplifies APIs — same method name for closely related operations.
  • Improves readability and discoverability.
  • Enables cleaner method signatures for different input types.

3. Runtime Polymorphism (Dynamic Polymorphism)

Runtime polymorphism is resolved at run time via method overriding. A parent class declares a method, and subclasses provide their specific implementations. When a parent type reference points to a subclass object, the JVM dispatches the call to the appropriate overriding method at runtime.

class Vehicle { void start() { System.out.println("Vehicle starting..."); } } class Car extends Vehicle { @Override void start() { System.out.println("Car starting with key..."); } } class ElectricCar extends Vehicle { @Override void start() { System.out.println("ElectricCar starting silently..."); } } public class Test { public static void main(String[] args) { Vehicle v; v = new Car(); v.start(); // Car's start() v = new ElectricCar(); v.start(); // ElectricCar's start() } }
Output (conceptual):
Car starting with key...
ElectricCar starting silently...

Why runtime polymorphism is crucial in Java

  • Supports flexible and extensible designs (open for extension, closed for modification).
  • Enables frameworks and libraries to call user-provided implementations (e.g., callbacks, listeners).
  • Allows building plug-and-play components — new subclasses can be added without changing existing code.

Industry note: Java frameworks (Spring, Hibernate, servlet containers) rely heavily on runtime polymorphism for inversion of control, proxying, callback handlers and dynamic dispatch.

4. More Real-time Examples (Java context)

Example — Payment Gateway (Runtime polymorphism)

Suppose a system supports multiple payment methods: CreditCard, UPI, Wallet. All implement a common interface `Payment` with a method `process()`. At runtime, the chosen payment provider's `process()` executes — same call, different implementations.

interface Payment { void process(double amount); } class CreditCard implements Payment { public void process(double amount) { System.out.println("Processing CC: " + amount); } } class UPI implements Payment { public void process(double amount) { System.out.println("Processing UPI: " + amount); } } class Wallet implements Payment { public void process(double amount) { System.out.println("Processing Wallet: " + amount); } } public class Checkout { static void pay(Payment p, double amt) { p.process(amt); } public static void main(String[] args) { pay(new CreditCard(), 1500.0); pay(new UPI(), 250.0); pay(new Wallet(), 99.0); } }
Output (conceptual):
Processing CC: 1500.0
Processing UPI: 250.0
Processing Wallet: 99.0

Example — UI Controls (Compile-time & Runtime together)

Overloaded methods render controls with different parameters (compile-time). The `draw()` method in `Control` might be overridden by `Button`, `TextField` subclasses (runtime).

Practice Questions — Click to reveal answers

1️⃣ What is polymorphism?
Polymorphism allows the same operation to exhibit different behaviors depending on the object performing it.
2️⃣ What is compile-time polymorphism?
Compile-time polymorphism is method overloading; the compiler decides which overloaded method to call based on parameters.
3️⃣ What is runtime polymorphism?
Runtime polymorphism is method overriding; JVM decides at runtime which overridden method to call based on the actual object's type.
4️⃣ How does polymorphism help in frameworks?
Frameworks use polymorphism to call user-defined implementations or proxies at runtime without knowing concrete classes at compile time.
5️⃣ Give a short real-time example of polymorphism.
Different vehicle types implementing a common start() method — the system calls start() but the concrete behavior depends on the vehicle.

Quick Summary

  • Polymorphism = many forms. Same method name, different behavior.
  • Compile-time (static) polymorphism = method overloading (resolved by compiler).
  • Runtime (dynamic) polymorphism = method overriding (resolved by JVM at runtime).
  • Polymorphism increases extensibility, flexibility and is heavily used in Java frameworks.
