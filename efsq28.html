28. Problem Statement for Full-Stack: Railway Scheduling Dashboard

You are required to build a **Railway Scheduling Dashboard**, similar to systems used in railway operations, control rooms, and smart transit planning. The dashboard must display **train timings, routes, passenger capacity**, and classify train status. Students will design a clean interface showing **train schedule data**, **on-time performance**, and **crowd level classification**.

Technological Requirements

  • Technologies to Use:
    • HTML — dashboard layout
    • CSS — styling & presentation
    • JavaScript — scheduling & classification logic
  • JavaScript Concepts Allowed:
    • Objects & Arrays
    • Arrow Functions
    • Event Handling
  • Restrictions:
    • No external libraries/frameworks
    • Frontend only

Functional Requirements

  • 1. Train Schedule Data Handling:
    • Create an array of train objects:
      { trainName, route, arrivalTime, departureTime, passengerCount }
    • Display all train data in an HTML table.
  • 2. Train Crowd Level Classification:
    • Calculate crowd density using:
    • crowdLevel = passengerCount
    • Classify trains:
    • • ≤ 300 → Low Crowd
      • 301–700 → Moderate Crowd
      • > 700 → High Crowd
    • Display classification next to each train.

Testing Requirements

Validate your railway scheduling dashboard with the following 2 test cases:

  1. Test Case 1 — Low Crowd Train:
    • Input: passengerCount = 250
    • Expected Output: Low Crowd
  2. Test Case 2 — High Crowd Train:
    • Input: passengerCount = 900
    • Expected Output: High Crowd
